Why I'm moving from sysadmin to DevOps

For a while now, my job has been keeping systems alive: patching servers, managing user access, responding when something goes down at 2am, restoring from backups when it does. It's real work, and I've gotten good at it. But somewhere in the last year, the part of the job I actually looked forward to stopped being the troubleshooting and started being the automation I built to avoid the troubleshooting in the first place.

That's the real reason I'm making this switch. Not because sysadmin work isn't valuable, but because I noticed I was happiest writing a script to handle something so I'd never have to do it manually again. DevOps is basically that instinct, formalized and scaled up.

What sysadmin work already taught me

I don't think of this as starting from zero. Years of keeping infrastructure running gave me things a lot of DevOps material assumes you already have:

  • An instinct for what actually breaks in production, not just what breaks in a tutorial.
  • Comfort with the command line, networking basics, and reading logs under pressure.
  • A healthy respect for backups, rollback plans, and change control, the stuff that doesn't show up in a demo but matters at 3am.

What I'm adding on top of that is the automation-first mindset: infrastructure as code instead of manual configuration, containers instead of hand-tuned servers, and metrics/logs/traces instead of "let me SSH in and take a look."

What year one looks like

I'm building this out roughly in this order: containers first (Docker), then orchestration (Kubernetes), then infrastructure as code (Terraform and Ansible), then observability (Grafana, OpenTelemetry, Loki), all on top of AWS as the cloud I'm learning deepest. This blog is where I'm writing down what actually clicks and what doesn't, mostly so future-me has notes, and partly because writing something down is the fastest way I know to find out if I actually understood it.

If you're a sysadmin thinking about the same move: the skills you already have are not a detour, they're the foundation. You're not starting over, you're specializing.
