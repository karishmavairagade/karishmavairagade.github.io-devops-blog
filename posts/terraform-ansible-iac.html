Terraform + Ansible: infra as code without losing sysadmin instincts

The hardest habit to unlearn as a sysadmin moving into infrastructure as code wasn't a tool, it was clicking around a console or SSHing in to fix something by hand. Every manual fix is a fact about your infrastructure that lives only in your memory until the next person (or the next incident) finds out the hard way. Terraform and Ansible fix that in two different, complementary ways, and untangling which one does what is what finally made both of them click.

Two different questions

Terraform answers: what infrastructure should exist? It's declarative, you describe the end state, an EC2 instance, a VPC, a security group, and Terraform figures out how to get there and keeps a state file so it knows what it already created.

Ansible answers a different question: once that machine exists, what should be installed and configured on it? It's more procedural, run this playbook, install these packages, template out this config file, restart this service.

Trying to make one tool do both jobs was where I kept getting stuck. Splitting them cleanly is what made the workflow feel natural:

# terraform: provision the box
resource "aws_instance" "app" {
  ami           = "ami-xxxxxxxx"
  instance_type = "t3.micro"
  tags = { Name = "app-server" }
}

# ansible: configure the box
- hosts: app_servers
  tasks:
    - name: install nginx
      apt:
        name: nginx
        state: present

Where my old instincts still matter

Infra as code doesn't replace sysadmin judgment, it just gives it a place to live permanently instead of in my head:

  • I still think about blast radius before applying anything, the same way I did before running a change on a production server.
  • I still read the plan output line by line before terraform apply, the same way I used to read a change ticket before touching anything.
  • Idempotency, a word Ansible cares about a lot, is just "if I run this twice, nothing bad should happen," which is exactly what I always wanted from my old shell scripts.

Next on the list: wiring up Grafana, OpenTelemetry, and Loki so I can actually see what all this provisioned, configured infrastructure is doing once it's running, not just trust that it's fine.
